# 常见问题与排查

[返回文档索引](README.md) · [双界面操作](uppermachine_processing.md)

## 启动找不到 RadarControlMachineApp 或 pradar

在包含 `startup.m` 的根目录执行 `startup`，然后检查：

```matlab
pwd
which startup -all
which RadarControlMachineApp -all
which pradar.defaultConfig -all
```

若出现多个工程副本，确认实际命中的是当前功能分支所在目录。不要在旧App窗口中检验新文件：先关闭界面1/2，再创建新实例。不要用强制重置Git来覆盖尚未保存的本地修改。

## 找不到 JSON / 无法写配置或数据目录

确认完整工程包含 `uppermachine/third_party/ti_postproc/AM273X_Capture.json`。源码App即便只做离线查看，也会初始化runtime JSON和默认数据目录。当前runtime通常写在CLI目录，数据目录为 `C:\CaptureData`；检查写权限，不要只复制主界面文件。详见[采集路径](acquisition.md)。

## 提示 medfilt1、hann 不存在

界面1现有RD路径需要 Signal Processing Toolbox。先在MATLAB中检查 `ver`、`which medfilt1` 和 `which hann`，不要把函数缺失误认为BIN损坏。只执行公共Core不代表界面1也能绕过这些调用。

## 更新后仍看到旧解模糊按钮、旧趋势图或多条当前帧线

核对分支和本地改动：

```bash
git status
git branch --show-current
git log -1 --oneline
```

双界面职责调整对应 `c8c4aa0`，单一SNR标度线修复对应 `f9f38e3`。这些是识别历史修复的提交，不要求最新HEAD正好等于它们。关闭旧App、检查 `which RadarControlMachineApp -all` 后重新启动；标度线可用 `regression_snr_frame_marker` 复查。

## 16/32/64 Chirp 修改后图空白或最大SNR异常

修改参数后重新“加载文件”，让RD缓存和轴按新窗长重建。若是旧代码的 `vel_axis(dIdx)` 越界，应更新包含缓存清理和尺寸检查的版本。

空图还有其他原因：界面1最大点搜索会屏蔽两侧Doppler边缘，默认 `Td=4,Gd=2` 对应每侧7列；16点窗口只剩2列。再叠加速度/距离门可能没有有效搜索区域。核对训练/保护单元与窗长的匹配，不要把全部NaN当成“确定没有目标”。

## 两个界面的RD或dB数值不一致

这是需要先检查处理配置的情况：界面1固定慢时间去均值、含中值滤波、按RX幅度相加；界面2首次默认关闭去均值、按RX功率相加，并使用独立背景增强。窗长、FFT、门范围和背景也可能不同。参见[算法流程](algorithm.md)，不要直接比较两个色条的数值判断增益。

## SNR高峰很多，哪些帧才是目标

全图最大值不是目标确认；杂波也会产生峰。先缩小到实验相关的距离/模糊速度观察范围，再把可疑物理帧送入界面2，以候选轨迹及几何一致性复核。更改观察门会改变最大值统计，应保存配置以便比较。

## 界面2无候选、无轨迹或速度全NaN

按顺序检查：BIN布局和物理参数 → 背景是否含目标 → 目标区间与相对时间门 → 候选距离与增强门限 → d、接近/远离和投影阈值 → 沿轨迹速率范围 → 模糊数搜索范围。

`R<=d`、近最近点投影过小会被拒绝；跨最近点需分段。`GeometryValid=true` 仍不保证存在满足范围的解模糊路径。必要时检查导出表和MATLAB警告；不要简单放宽所有门限或把参考速率调到预期答案。

## 测速看起来平滑但数值不合理

确认帧周期是否真为3.5 ms，Chirp周期是否真为12 μs，横向距离是否为三维最短距离，以及实际IQ/Doppler符号是否与方向约定一致。`UnwrappedVelocity_mps` 是径向速度，目标沿轨迹速率应查看 `TargetSpeed_mps`。RMSE相对的是参与选解的输入参考值，不是自动提供的独立精度认证。

## 样本10帧却要求输入第134帧

案例配置使用完整文件帧号，裁剪样本使用文件内1～10。源帧126映射到样本帧1；原始背景区间未必全部在裁剪样本中。参见[data说明](../data/README.md)，不要直接套完整案例配置。

## 文件加载慢或内存不足

界面1仍逐窗读文件并预计算全部SNR；界面2会建立所选区间RD Cube。先缩小事件区间和背景帧，检查步进/FFT；取消“保留完整RD Cube”只减少返回与导出大小，不消除处理峰值内存。

## 导出CSV缺失或像是旧结果

候选/轨迹为空时，对应CSV不会生成。导出的是上一次已完成结果，改参数后须重新运行；同名BIN使用同目录可能覆盖文件，旧CSV也可能混在新结果旁。每次实验/参数版本使用独立输出目录。

## 采集成功但日志出现溢出，或关闭窗口后仍有采集进程

按[采集说明](acquisition.md)处理。当前没有完整的异常自动判定/关闭清理保障，“stop_record返回成功”“文件还增长”“GUI显示完成”均不能独立证明数据完整。

## 反馈问题时附上什么

提供分支与提交号、MATLAB和操作系统版本、完整报错栈、操作顺序、参数截图或 `result.cfg`、BIN字节数/帧数/尾部字节、可共享的最小复现数据。涉及显示问题再附截图；分享前去除账号、内部路径和敏感实验信息。不要仅提供一张曲线而缺失处理参数。
