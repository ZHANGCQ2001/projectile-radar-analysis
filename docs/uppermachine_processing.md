# 双界面使用说明

[返回文档索引](README.md) · [参数说明](parameters.md) · [常见问题](troubleshooting.md)

## 1. 分工与启动

界面1 `RadarControlMachineApp` 用于手动采集、整体浏览与选帧；界面2 `radarui.ProcessingWindow` 用于选定区间的候选检测、几何轨迹拟合及测速。界面1旧的单点解模糊和拟合趋势功能已删除。

在工程根目录运行：

```matlab
startup
app = RadarControlMachineApp;
```

更新代码后关闭旧窗口并重新创建 App。离线浏览无需连接板卡，但启动仍会读取 JSON 模板和初始化可写路径；依赖见[项目 README](../README.md)。

## 2. 界面1：先整体查看

选择完整路径的 BIN 文件，在“参数配置”中确认 ADC 复数采样点、Chirp 数、RX 数、采样率、斜率、Chirp 周期等与固件一致。这里修改的是上位机解析/处理参数，不会因此自动改写雷达固件的发射配置。

点击“加载文件”。当前实现会计算全部滑窗的最大 SNR，再刷新第一窗；大文件或很小的步进可能等待较久，并非流式实时检测。

| 视图 | 内容与预处理 |
|---|---|
| 频点 RD 图 | 距离 bin / Doppler bin 坐标；当前滑窗复数 ADC 经慢时间中值滤波、慢时间去均值，再加窗 FFT |
| 物理坐标 RD 图 | 与频点图来自同一 RD 结果，速度维 `fftshift` 后用距离和模糊径向速度标注；不是另一套测速算法 |
| 原始 ADC 数据图 | 热力图读取当前窗原始 ADC；波形可选原始 I/Q、去均值 I/Q、相邻差分 I/Q，不能把波形显示选择当成 RD 模式开关 |
| 一维 FFT 图 | 来自原始 ADC 读取路径的 Range FFT，不继承 RD 路径全部预处理 |
| 最大 SNR 趋势图 | 物理帧号与每帧最大 SNR 指标，用于定位待分析区间 |

### 慢时间去均值

界面1 `computeWindowRd()` 固定执行：

```matlab
adcOutFrame = adcOutFrame - mean(adcOutFrame, 2);
```

对每个 Sample、每个 RX，在**当前滑窗的 Chirp 维**减去复数均值，位置在 FFT 前。窗口缩短时，求均值的范围也缩短。当前界面1没有启停勾选框；界面2的勾选不会改变界面1。

### 每帧最大 SNR 和当前帧标记

每个滑窗先在有效距离/模糊速度门内找到最大局部对比值，再由 `radarui.summarizeFrameSnr()` 对该物理帧的有效滑窗取最大。不是对 dB 求平均，也不是绘制该点的距离或速度。

一帧有多个滑窗时，物理帧号为：

```text
physicalFrame = floor((windowIndex - 1) / windowsPerFrame) + 1
```

滑块和前后按钮移动的是滑窗；同一物理帧中的不同滑窗共享同一个横坐标标记。始终只有一条“当前帧”线；换文件或参数失效时清空旧标记和趋势。没有有效值的帧保留 NaN，避免伪造为 0 dB。

SNR 指标定义及其与界面2背景增强的区别见[算法文档](algorithm.md)。“有效滑窗 N/N”只说明得到了有限值，不表示每个窗口都检测到弹丸。

## 3. 从界面1选帧进入界面2

在最大 SNR 图定位事件后，填写“目标起始帧”和“目标终止帧”，点击“界面2：精细处理”。帧号必须在当前 BIN 的 `1~总物理帧数` 内。

传入的是 BIN 路径、基础雷达参数和目标物理帧区间。界面2的短时处理窗独立设置，不自动等同于界面1浏览窗。背景初值尽量取目标区间前最多 10 帧，但**必须人工确认背景不含目标**；目标从第 1 帧开始时，默认背景可能与目标重叠，界面会提示，程序不会凭空补出目标出现前的数据。

再次从界面1打开已有界面2时，会保留已输入的横向距离、方向、最小投影、参考速率及速率上下限；其他参数可能由传入配置重新填充。因此重开窗口后仍应核对处理窗、帧周期、背景区间和去均值勾选状态。不要理解为保存了所有参数的持久化配置。

## 4. 界面2：精细目标检测

按下列顺序确认参数后点击“开始处理”：

1. **数据与时序**：背景/目标物理帧，帧周期 ms，短时窗/步进，Doppler FFT。
2. **检测范围**：候选距离门、候选增强门限、每窗候选数；显示范围仅影响显示，不放宽算法搜索门。
3. **几何与速率**：横向距离 d、接近/远离、最小投影、沿轨迹参考速率和上下限。
4. **关联约束**：轨迹容差、最少轨迹点、轨迹时间门、速度硬门限和最小绝对模糊速度。

横向距离 d 是雷达至直线轨迹的最短距离。存在高度差时用三维最短距离。各点斜距 R 由候选数据提供，不需要手填一个固定目标距离。参考速率及上下限使用沿轨迹速率正值，接近/远离通过方向框选择，详见[几何模型](track_fitting.md)。

首次从界面1进入时，处理默认值包括 16/16 Chirp、128 点 Doppler FFT、3.5 ms 帧周期、d=0、参考速率 400 m/s、慢时间去均值关闭。这些都是初始配置，尤其帧周期与几何量必须按真实工况修改。

轨迹时间门单位 ms，以**目标所选区间第一物理帧起点**为时间原点；不是整个 BIN 第 1 帧时间，也不是界面1上的物理帧号。

“取消”由处理控制器的取消检查点响应，不是独立实时任务。处理结束状态不等于必然有有效轨迹，需要继续核对结果。

## 5. 结果页如何读

| 页面 | 当前显示 |
|---|---|
| 结果摘要 | 数据区间、候选/轨迹数量、几何拟合沿轨迹速率、斜距残差 RMSE、有效测速点、相对参考速率差异 |
| 候选目标RD | `range` 模式下是**时间—距离背景增强图**及候选/轨迹覆盖，白色虚线标示候选距离门；不是单张平均 R-D 图 |
| 候选与轨迹 | 距离—时间候选散点、最终关联点和几何距离拟合曲线 |
| 速度 | 有模糊径向速度、解模糊径向速度、逐点折算沿轨迹速率及参考速率 |

`velocity` 投影会改变候选产生方式；“候选目标RD”页没有时间—距离图时会提示切回 `range`，并不等于其他结果无效。两种投影共用几何轨迹关联。

没有轨迹时先核对数据格式、目标/背景范围、距离门、d 与 R 的关系、方向、速率范围；不要直接把参考速率改到“想得到的数值”。参考值参与选解，相对它的低 RMSE 不是独立精度证明。

## 6. 导出与内存

“导出结果”会保存最近一次已完成的结果，而不是仅修改参数后尚未重算的结果。输出目录由用户选择：

```text
<bin>_processing_result.mat       # result 结构，-v7.3
<bin>_summary.txt                 # UTF-8 摘要
<bin>_candidates.csv              # 候选非空时写出
<bin>_track.csv                   # 轨迹非空时写出
```

不同参数处理同一 BIN 时建议使用不同输出目录，避免同名前缀覆盖或与旧 CSV 混淆。GUI 不自动生成 GIF；GIF 属于脚本入口的单独配置。

默认不保留完整 RD Cube，但处理过程中仍生成背景和目标 Cube；估计主要数组超过约 1.5 GiB 时会提示。该估算不是内存硬限制或完整进程占用保证。整体浏览后缩小目标/背景帧区间，比直接处理完整大文件更合适。
